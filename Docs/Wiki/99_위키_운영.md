# 위키 운영 규칙

> 이 문서는 개발자용이다(`ingame: false`). 게임 안 도움말에는 넣지 않는다.

## 1. 파일 구조
- 경로: `Docs/Wiki/NN_이름.md`. 번호는 묶음을 나타낸다.

| 번호 | 묶음 |
|---|---|
| 0x | 기초 |
| 1x | 허브 |
| 2x | 탐험 |
| 3x | 사람들 |
| 4x | 바깥 세계·밤의 일 |
| 5x | 이야기 |
| 9x | 부록 |

- 문서 사이 링크는 상대 경로(`[글](24_지역.md#2-새벽고-교실동)`)로 건다.

## 2. 머리말
```yaml
id: wiki.locations      # 게임 안에서 부를 키. 바꾸지 않는다
title: 지역             # 도움말 목록에 보일 제목
category: 탐험          # 목차 묶음
spoiler: none|light|heavy
unlock: FLAG_ID         # (선택) 이 깃발이 켜진 뒤에만 보임
ingame: false           # (선택) 게임 안에 넣지 않음
```

## 3. 게임 안에서 읽히는 곳 (2026-11-26)
- 위키는 게임 안 PC통신 '이제누리'의 **생존 백과**에서 그대로 읽힌다([46_PC통신](46_PC통신.md)).
- 위키를 고친 뒤 저장소 루트에서 `python Tools/sync_wiki.py`를 돌리면 `Assets/_Project/Resources/Bbs/wiki.json`이 다시 만들어진다. `ingame: false` 문서는 빠진다.
- 본문은 글자 화면(약 76칸)에 찍힌다. 표는 "칸 │ 칸"으로, 제목은 【 】·■로 바뀌고 링크·굵게·코드 표시는 걷힌다. 그래서:
  - `ingame: false`가 아닌 문서 본문에는 파일 경로·클래스 이름·깃발 ID·"개발판" 같은 개발자용 설명을 넣지 않는다.
  - 표의 칸은 짧게 쓴다. 긴 설명은 표 아래 목록으로 뺀다.
- 새 문서를 만들면 [00_대문](00_대문.md) 목차와 [91_용어집](91_용어집.md)에 넣는다. 이 운영 규칙 문서는 게임 안에 나오지 않으므로 대문 목차에 넣지 않는다.

## 3-1. 게임 안 도움말로 연결할 때(예전 제안)
1. **데이터로 둔다.** 마크다운 원본을 빌드 때 `Resources/Help/*.json`(제목·섹션·본문)으로 바꾼다. 화면 문자열 원칙(CLAUDE.md 작업 원칙 3)과 같다.
2. **열리는 조건**
   - `unlock` 깃발이 켜졌을 때만 목록에 보인다.
   - `heavy` 문서는 막이 끝난 뒤(또는 갤러리에 엔딩이 있을 때) 연다.
   - 엔딩 목록은 본 엔딩만 조건을 보여 준다.
3. **숫자 노출 정도**
   - 게임은 호감·감염 숫자를 숨기도록 설계했다.
   - 도움말에서도 **호감·감염의 정확한 값과 판정 공식은 빼거나 "설정 > 자세한 수치 보기"에서만** 보여 주기를 권한다.
   - 위키(외부)에는 그대로 둔다.
4. **들어가는 곳**
   - 메뉴의 "도움말"
   - 처음 보는 시스템이 열릴 때 뜨는 한 장짜리 팁 카드("자세히" → 해당 문서 절)
   - 출정 준비 화면의 "?" 단추 → [탐험 기초](20_탐험_기초.md)
5. **표**: UI Toolkit에서 표를 그리기 어렵다면 "이름 — 값" 목록으로 바꿔 그린다.
6. **`<details>` 접기**: 게임 안에서는 "스포일러 보기" 단추로 바꾼다.

## 4. 수치를 고칠 때
- 수치의 원본은 `Core/Definitions/BalanceConfig.cs`·`Content/**/*.json`이다. 밸런스를 바꾸면 이 위키의 해당 표도 고친다.
- 실제 값은 `BalanceConfig.cs` 기본값에 `Assets/_Project/Balance/balance_overrides.json`을 얹은 것이다. 덮어쓰기 파일에 값이 있으면 그쪽이 맞다.
- 큰 밸런스 조정(M7 마지막 목표 맞추기) 뒤에는 위키 수치를 한 번에 다시 맞춘다.
- 대문의 "수치 기준" 날짜도 함께 고친다.
- 아직 이름이 없는 것(좀비 3종 "배회형·청각형·감시형")은 위키 임시 명칭이다. 게임 안 이름이 정해지면 바꾼다.

## 5. 표현 원칙
- 콘텐츠 안전 가이드(마스터 프롬프트 13장)를 따른다. 잔혹한 묘사를 하지 않고, 괴롭힘은 암시로만 쓰며, 미성년 인물에 대한 외모 묘사는 최소로 한다.
- 문체는 "~다" 평서문으로 쓴다. 나무위키식 농담·드립은 넣지 않는다(게임 안 도움말과 겸용이기 때문이다).
