# 거점 탭 살리기 (기획 제안, 2026-11-25)

허브 상단 "거점" 단추로 여는 오른쪽 서랍(`drawer-right`, `StatusPanelView`)을 다시 짜는 제안이다.
지금은 단조롭고, 무엇에 쓰는 화면인지 잘 보이지 않는다(사용자 의견 2026-11-25).

- 한 줄 요약: 거점 서랍을 **"거점 상황판"**으로 바꾼다.
  - 이번 주에 거점이 얼마나 안전한지, 무엇이 모자라는지, 다음에 무엇을 하면 좋은지를 한 화면에 보여 준다.
  - 항목을 누르면 단면도의 그 방이나 계획 보드의 그 행동으로 바로 간다.
- 새 규칙이나 수치는 더하지 않는다. 이미 있는 규칙(`RaidRules`·`DefenseRules`·`PowerRules`·`PurifyRules`·`ScarecrowRules`·`RoleRules`)을 **읽어서 보여 주기만** 한다. 세이브는 바뀌지 않는다.

## 1. 지금 모습과 문제

### 1.1 지금 서랍에 있는 것 (`HubViews.cs` `StatusPanelView`)

```
┌ 거점 · 사람 · 세력 ──────────── ✕ ┐
│ 거점                                │
│ 시설: 본관 창고, 교실동, 보건실, …  │  ← 글 한 줄
│ 윤 선생님 · 걸을 수 있음            │
│ [얼굴] 도현 · 경비                  │  ← 누르면 역할이 차례로 바뀜
│ [얼굴] 하린 · 역할 없음             │
│ 세력                                │
│ [사거리 파 · 경계 −12]              │
│ ▓▓▓▓░░░░░░                          │
│ 요즘 교문 쪽을 기웃거린다.          │
└─────────────────────────────────────┘
```

### 1.2 문제

| # | 문제 | 왜 그런가 |
|---|---|---|
| ① | **시설이 이름뿐이다** | 보건실 감염 저항, 도서관 교육 +15%, 과학실 공학·의학 판정 +10%, 체육관 습격 경비 +4가 데이터(`traits_facilities.json` `Modifiers`)에는 있다. 그런데 화면에는 이름만 나온다. 방을 열어도 무엇이 좋아졌는지 모른다 |
| ② | **역할 바꾸기가 숨은 조작이다** | 단추를 누를 때마다 다음 역할로 넘어간다. 어떤 역할이 있는지, 정원(2)이 찼는지, 방이 몇 개 열려 효과가 몇 배인지, 적성이 맞는지가 보이지 않는다. 인물 서랍(`PeopleDrawerView`)에도 역할이 보이지만 보기만 할 수 있다. 같은 정보가 두 곳에 다른 모양으로 있다 |
| ③ | **거점의 위험이 보이지 않는다** | 밤 습격 확률은 위협−방어, 비, 방송, 세력, 허수아비, 함정, 경보에 따라 바뀐다(`RaidRules.Chance`). 그런데 화면에는 상단의 "방어 20 · 위협 50" 칩 하나만 있다. 이번 주가 위험한지, 무엇을 하면 나아지는지 알 수 없다 |
| ④ | **살림 상태가 흩어져 있다** | 전력 여유/용량은 상단 칩, 냉장고는 보이지 않고, 정수 설비는 단면도 그림에만 있다. 식량 부패 문턱(60, 냉장고 +30), 빗물통·텃밭 수확, 고양이 급식(주 1)은 결산에서 지나간 뒤에야 안다 |
| ⑤ | **단면도와 따로 논다** | 단면도는 방을 누르면 그 방의 행동이 나오는 "공간 메뉴"다. 그런데 거점 서랍은 단면도와 이어지지 않는다. 서랍을 열어도 할 수 있는 일이 없다(역할 단추 빼고) |
| ⑥ | **다음 목표가 없다** | 잠긴 방(가사실·음악실·컴퓨터실 수색, 특수실)은 어떻게 여는지, 다음에 지을 설비는 무엇인지 알려 주지 않는다. 거점이 커 가는 맛이 서랍에 없다 |

결국 지금 서랍은 **"이미 아는 것을 글로 다시 읽는 곳"**이다. 판단에 쓰는 화면이 되어야 한다.

---

## 2. 목표

1. **10초 안에 이번 주 거점 상태를 읽는다**: 안전한가, 모자라는 게 있나, 고장 난 게 있나.
2. **이유가 보인다**: 위험이 "높음"이면 왜 높은지(위협이 방어보다 30 높음, 비, 방송한 주) 한 줄씩 보인다.
3. **바로 할 수 있다**: 상황판 항목 → 계획 보드의 그 행동, 또는 단면도의 그 방.
4. **커 가는 게 보인다**: 연 방·지은 설비·다음에 열 수 있는 것이 칸으로 쌓인다.

## 3. 추천안: 거점 상황판

### 3.1 화면 구성 (오른쪽 서랍, 위에서 아래로)

```
┌ 거점 ─────────────────────────── ✕ ┐
│ ⚠ 알림 (있을 때만, 빨간 띠)          │
│   발전기 고장 · 허수아비가 쓰러졌다  │
├──────────────────────────────────────┤
│ 🛡 안전          이번 주 밤 습격: 높음│
│  방어 ▓▓▓▓░░░░░░ 20/60               │
│  위협 ▓▓▓▓▓▓▓▓░░ 50                  │
│  왜: 위협이 방어보다 30 높다         │
│      비가 와서 덜 온다 (좋은 쪽)      │
│  함정 ●●○  경보 ✓  허수아비 ▮▮▯      │
│  [바리케이드 보강] [함정 놓기]       │  ← 누르면 계획 보드
├──────────────────────────────────────┤
│ 🍚 식량과 물    다음 결산 예상        │
│  식량 42  (아침 −21 · 텃밭 +10 · 급식 −1) │
│  물   18  (식단 −21 · 빗물 +6 정수 필요) │
│  ⚠ 물이 이번 주를 못 넘긴다           │
│  부패 문턱 90 (냉장고 켜짐)           │
├──────────────────────────────────────┤
│ ⚡ 전력   ■■■□  여유 1 / 용량 3       │
│  냉장고 1 · 자동 정수기 1             │
│  배터리 3/5 → 용량 +1                 │
├──────────────────────────────────────┤
│ 🏫 시설  (연 방 9 / 14)               │
│  [보건실]  [도서관]  [과학실]  [?]    │
│   감염↓    교육+15%  판정+10%  가사실 │
│  [체육관]  [교무실]  [옥상]    [?]    │
│  누르면 단면도에서 그 방이 빛난다     │
├──────────────────────────────────────┤
│ 👥 역할  (자세히 → 역할 판)          │
│  경비 도현·하린  정찰 —  간호 서진 ★ │
├──────────────────────────────────────┤
│ 🤝 세력                               │
│  사거리 파 · 경계   ▓▓▓░░  (누르면 거래)│
└──────────────────────────────────────┘
```

- 칸마다 머리글 오른쪽에 **한 단어 판정**(높음·위험·여유·부족)을 둔다. 서랍을 열자마자 눈이 그쪽으로 간다.
- 칸을 접고 펼 수 있다(펼침 상태는 `PlayerPrefs`, 탐험 자동 설정처럼). 처음에는 다 펼친다.
- 1주차 창고에 갇힌 동안과 거점이 생기기 전에는 지금처럼 단출하게 둔다(`Disclosure`). 칸은 그 시스템이 열린 뒤에 나온다. 예: 안전 칸은 `UI_DEFENSE` 뒤, 전력 칸은 `POWER_RESTORED` 뒤.

### 3.2 칸별 내용과 쓰는 규칙

| 칸 | 보여 줄 것 | 계산 (모두 읽기만, 난수 안 씀) |
|---|---|---|
| **알림** | 고장·쓰러짐·멈춤·바닥 | 발전기 고장 `GENERATOR_BROKEN`, 허수아비 쓰러짐(`CRAFTED_ACT_CRAFT_SCARECROW`이고 `SCARECROW_UP` 없음), 정수기 멈춤 `PurifyRules.PurifierStopped`, 정전 `IsBlackout`, 다친 동료 수, 습격이 뚫린 주 `LAST_RAID_BREACHED` |
| **안전** | 이번 주 밤 습격 가능성(단계), 이유 줄, 방어/위협 막대, 함정·경보·허수아비 내구 | 밤 한 번 확률 `RaidRules.Chance` → 이번 주 남은 밤 수 n에 대해 `1 − (1 − p)^n`. 단계: 낮음 <15% · 보통 <35% · 높음 그 이상(문턱은 `BalanceConfig`에 새 절로). 이유 줄: 위협−방어 차이, 비(`RainRaidMultiplier` 0.6 — 비 오는 주는 **덜** 온다), 방송한 주(`BroadcastRules.RaidMultiplier`), 세력(`FactionRules.RaidChanceMultiplier`), 난이도. 3막부터는 낮 침입 가능성 줄도(`IntrusionRules.WeeklyChance`) |
| **식량과 물** | 지금 양, 다음 결산까지 예상 증감, "못 버틴다" 경고, 부패 문턱 | 식단 소비 = 사람 수 × 하루 몫(`FoodDiet`·`WaterDiet`) × 남은 날. 수확 = 텃밭(`ROOF_GARDEN`, 겨울 제외)·빗물(`RAIN_BARRELS`, 비 오는 주, 정수 전 `RawWater`); 고양이는 결산 때 식량 1을 먹는다(`CatFoodPerWeek`, 보태지 않는다). 부패 문턱 = `FoodSpoilageThreshold` + `PowerRules.FoodSpoilageBonus`. 계획에 든 정수·요리 행동은 "+?"로만 쓴다(판정이 있어서) |
| **전력** | 용량 칸(■), 켜진 기기와 몫, 여유, 다음 증설까지 배터리 | `PowerRules.Capacity`·`Powered`·`Free`·`UpgradeCost`, 가진 배터리 |
| **시설** | 연 방은 아이콘 + 효과 한 줄, 잠긴 방은 "?" + 여는 방법 힌트 | 효과 문구는 `facility.{ID}.effect`(새 문구 키). 잠긴 방 힌트는 `hubroom.{ID}.hint`(예: "교실동 3층을 뒤지면"). 방의 열림 조건은 `hub_section.json` `Rooms`의 `Facility`/`Flag` 그대로 |
| **역할** | 역할마다 맡은 사람 한 줄, 빈 역할·정원 넘침·방 없음 경고 | `RoleRules.Choices`·`RoomScale`·`HasAptitude`·`IsActive` (4절 역할 판) |
| **세력** | 이름·단계·평판 막대 한 줄씩, 근황은 마우스를 올렸을 때 | 지금 코드 그대로, 접어서 한 줄로 |

### 3.3 누르면 가는 곳 (단면도·계획 보드와 잇기)

| 누르는 것 | 가는 곳 |
|---|---|
| 안전 칸의 행동 단추(바리케이드·보강·함정·경보·가림막·야간 경계) | 계획 보드를 열고 그 행동을 고른 상태로 (`PaletteView.Select`, 단면도 방 행동과 같은 길 `ActionPicked`) |
| 시설 칸의 방 | 서랍을 닫고 단면도에서 그 방에 빛 테두리 + 방 패널(`HubSectionView.ShowRoomPanel`) |
| 시설 칸의 잠긴 방 "?" | 힌트 말풍선만 (어디를 탐험하면 열리는지) |
| 식량·물 경고 | 계획 보드의 생존 탭 (정수·요리·텃밭 행동) |
| 전력 칸 "배터리 3/5" | 방송실 방 패널 (`ACT_SURV_UPGRADE_POWER`) |
| 세력 줄 | 세력 거래 화면 `FactionView` (지금 그대로) |

- 계획 단계가 아닐 때(실행 중)는 단추를 막고 보기만 한다. 지금 역할 단추와 같다.
- 마우스를 올리면 단면도에서 그 방이 살짝 빛난다. 서랍에 가리지 않는 방만 빛난다. 서랍이 오른쪽이라 왼쪽 방들이 보인다.

### 3.4 거점 단추의 경고 점

- 상단 "거점" 단추 오른쪽 위에 **빨간 점**을 띄운다. 알림 칸에 무언가 있거나, 습격 가능성이 "높음"이거나, 물·식량이 이번 주를 못 넘길 때다.
- 서랍을 열지 않아도 "거점에 볼 일이 있다"를 알 수 있다.
- 이번 주 계획을 짜는 동안 한 번 열어 보면 점이 사라진다. 다음 주에 새로 생기면 다시 뜬다.

## 4. 역할 판 (역할 바꾸기를 보이게)

누를 때마다 차례로 바뀌는 단추 대신, **역할 6칸 × 자리 2개** 판을 둔다.

```
┌ 역할 ──────────────────────────────────────────┐
│ 경비 (현관·교무실, 방 2 → ×1.25)  [도현][하린] │
│ 정찰 (옥상·방송실, 방 2)          [ + ][ + ]   │
│ 간호 (보건실)                     [서진★][ + ] │
│ 살림 (가사실 잠김 — 가사실을 뒤지면)  🔒       │
│ 공부 (교실·도서관·과학실 ×1.5)    [ + ][ + ]   │
│ 위로 (음악실 잠김, 체육관)        [ + ][ + ]   │
│                                                │
│ 쉬는 사람: [반장] [유랑자]                     │
└────────────────────────────────────────────────┘
```

- **[ + ]를 누르면** 그 역할에 넣을 수 있는 사람의 뱃지가 뜨고, 골라서 넣는다. 뱃지를 다른 칸으로 끌어 놓아도 된다. 넣은 사람을 우클릭하면 뺀다. 계획 보드의 "우클릭 = 비우기"와 같다.
- 역할 이름 옆에 **방 묶음과 배율**을 쓴다(`RoleRules.RoomScale`). 방이 하나 늘 때마다 +25%라서 "방을 열면 역할이 세진다"가 보인다.
- **적성 ★**(`BalanceConfig.RoleAptitudes`, ×1.25)을 뱃지에 붙인다. 적성 역할을 원하는 동료는 `people.wish.*` 문구를 마우스를 올렸을 때 보여 준다.
- 정원이 차면 [ + ]가 없다. 스트레스가 높아 효과가 반이 된 사람(`RoleRules.IsActive`)은 뱃지를 흐리게, 이번 주 외출하는 사람은 "외출" 표시를 단다.
- 바꾸는 함수는 지금 쓰는 `GameSession.SetNpcRole`을 그대로 쓴다. 규칙은 바뀌지 않는다.
- **자리**: 상황판 역할 칸의 "자세히"로 서랍 안에서 펼친다. 인물 서랍 카드의 역할 줄을 누르면 이 판으로 온다.

## 5. 단면도 방 패널 보강 (같이 하면 좋은 것)

방 패널(`HubSectionView.ShowRoomPanel`)에는 지금 이름·그림·지은 설비·행동 단추가 있다. 여기에 두 줄을 더한다.

- **이 방의 효과**: 시설 칸과 같은 문구(`facility.{ID}.effect`). 예: "도서관 — 수업에서 얻는 숙련 +15%".
- **여기 있는 사람**: 이 방을 맡은 역할의 동료와 적성 ★. 비어 있으면 "맡은 사람이 없다 — 역할 판에서".

거점 서랍과 단면도가 같은 말을 쓰게 된다. 방을 눌러 본 사람도, 서랍을 연 사람도 같은 것을 배운다.

## 6. 다음 할 일 한 줄 (선택)

상황판 맨 아래에 **"지금 해 두면 좋은 일" 한두 줄**을 둔다. 조건과 문구는 데이터로 둔다.

- 파일: `Content/Base/base_advice.json` (줄마다 조건·우선순위·문구 키·누르면 고를 행동 ID). 조건은 이벤트와 같은 `ConditionEvaluator`로 읽는다.
- 예:
  - 위협이 방어보다 20 넘게 높다 → "교문을 더 막아 두자" → `ACT_SURV_BARRICADE`
  - 함정 0, 습격 가능성 높음 → "함정을 놓아 두자" → `ACT_SURV_TRAP`
  - 식량이 부패 문턱보다 많다 → "남는 식량이 상한다. 나눠 주거나 냉장고를" (배분 화면 안내)
  - 배터리가 증설 비용 이상 → "발전 용량을 늘릴 수 있다" → `ACT_SURV_UPGRADE_POWER`
  - 허수아비 쓰러짐 → "허수아비를 다시 세우자" → `ACT_CRAFT_SCARECROW`

## 11. 결정과 진행

- **결정 (사용자 2026-11-25, 추천안대로)**: B1 단계 말 + 이유 줄 · B2 거점 서랍 역할 판 · B3 다음 할 일 줄 넣음(1~2줄, 선생님 말투) · B4 세력은 거점 서랍에 접힌 한 줄씩.
- 이 문서를 쓴 뒤 바로잡은 것: 고양이는 식량을 보태지 않고 결산 때 1을 먹는다. 비 오는 주는 습격이 **줄어든다**(×0.6). 3절 그림과 표를 고쳤다.

### P1 완료 (2026-11-25)

- 코어 `BaseForecast`(`Core/Rules/BaseForecast.cs`, 읽기만·난수 안 씀):
  - `Raid`: 남은 밤 중 거점에 있는 밤만 센다. 밤 탐험과 창고에 갇힌 칸은 빼고, 그 수를 `NightsAway`·`NightsOut`에 둔다. 그 밤들에 대해 `1 − (1 − p)^n`을 계산하고 단계를 정한다.
  - 막을 가능성 `RepelChance`: 세기와 방어력의 흔들림을 모두 세어 낸다. 식은 `RaidRules.Resolve`와 같고 함정·경보·허수아비를 넣는다.
  - 이유 줄: 위협−방어, 비, 방송, 세력, 밤 탐험.
  - 낮 침입 가능성: `IntrusionRules.Roll`과 같은 식이다.
  - `Food`·`Water`: 남은 아침과 주간 정산을 실제 순서대로 따른다. 식량은 텃밭 → 부패 → 고양이, 물은 자동 정수기 → 아침, 그다음 생활용수·빗물 → 모래 필터 순이다. 처음 모자라는 날도 낸다.
  - `Power`: 용량·켜진 기기·배터리.
  - `Alerts`: 발전기 고장, 정수기 멈춤, 허수아비 쓰러짐, 지난 습격 뚫림, 다친 동료, 식량·물 바닥, 습격 높음.
- 단계 문턱은 `BalanceConfig` 거점 상황판 절이다: 습격 0.15·0.35, 막기 0.8·0.5.
- 화면 `BaseBoardView`: 거점 서랍 맨 위에 알림 띠와 안전·식량과 물·전력 칸이 있다.
  - 칸 머리를 누르면 접히고(`PlayerPrefs` `ApoGirl.BaseBoard.Fold.*`), 머리 오른쪽에 판정 칩이 있다.
  - 계획 중에만 행동 단추가 최대 3개 나온다. 누르면 서랍을 닫고 계획 보드에서 그 행동을 고른다.
  - 안전 칸은 `UI_DEFENSE` 뒤에, 전력 칸은 발전기 복구 뒤에 나온다.
  - 머리 아이콘은 있는 것을 썼다(`hub.defense`·`res.Food`·`res.Power`).
- 거점 단추의 빨간 점(`HubLayers.SetBaseAlert`): 알림이 있으면 뜨고, 서랍을 열면 본 것으로 친다. 주가 바뀌거나 새 알림이 생기면 다시 뜬다.
- 문구 `ko.json` `base.*`·`appliance.*`, 스타일 `Theme.uss` `.base-*`·`.hud-alert-dot`.
- 테스트 `BaseForecastTests` 5개: 식량·식수·빗물 예상 = 실제 한 주, 모자라는 날, 상태·난수 그대로, 남은 밤·밤 탐험·습격 단계, 막을 가능성.
- 기존 시설 글·역할 단추·세력 칸은 그 아래에 그대로 있다(P2·P3에서 바꾼다).

### P2 완료 (2026-11-25)

- 기획의 `facility.{ID}.effect`(방마다 한 문구) 대신, **효과는 시설 데이터에서 만든다**: `traits_facilities.json` `Modifiers`의 종류마다 문구 `facility.mod.{Kind}`(값은 `{0}`, 판정 보너스의 숙련 이름은 `{1}`). 수치를 바꾸면 화면 말도 따라 바뀐다.
- 효과가 없는 방(현관·창고·교실·가사실·방송실·음악실·컴퓨터실·옥상)은 쓰임 `hubroom.{ID}.use`("수업 — 선생님과 공부")를 보통 글자색으로 쓴다. 효과는 초록.
- 잠긴 방은 "? 이름" + 여는 방법 `hubroom.{ID}.hint`(예: "교실동 1층 가사실을 뒤지면 쓸 수 있다", 특수실은 "19주차 뒤 교실동을 탐험하면 연다").
- 시설 칸(상황판, 전력 아래): 단면도 방 표(`hub_section.json` `Rooms`) 차례로 연 방 먼저, 판정 칩 "연 방 n / 14". 아이콘은 거점 단추 그림 `menu.school`.
- 단면도 연동: 줄에 마우스를 올리면 그 방에 빛 테두리(`HubSectionView.Highlight`, `.hub-ring`), 누르면 서랍을 닫고 `FocusRoom`(테두리 2.5초 + 방 패널). 잠긴 방도 패널이 뜨고 힌트가 나온다.
- 방 패널: 효과 줄(초록) + "○○ 자리: 맡은 사람 ★"(이 방이 묶인 역할 `RoleDef.Rooms`, 비었으면 역할을 맡기라는 안내). 1층 방 패널은 단면도 아래로 넘치지 않게 위로 당긴다.
- 공용 문구 `RoomText`(상황판·방 패널이 같은 말), 방 열림·이름은 `HubSectionConfig.IsRoomOpen`·`RoomName`으로 옮김.
- 옛 "시설: 본관 창고, …" 한 줄은 뺐다(선생님 상태 줄은 남음).
- 테스트 `BaseRoomTextTests` 3개: 단면도 방마다 쓰임(늘 열린 방 빼고 힌트도) 문구, 시설 효과 종류마다 문구·숙련 이름, 역할 방 묶음이 단면도 방이고 한 방이 두 역할에 묶이지 않음.
