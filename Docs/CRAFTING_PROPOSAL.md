# 제작 기획: 제작 탭 + 교실 해금 + 3단계 테크트리

> 상태: **기획 확정, 구현 중 (P1~P3 끝)**. 2026-11-24에 쓰고, 같은 날 사용자가 C1~C10을 정했다(7절). 결정에 맞춰 본문을 고쳤다. P1~P3을 구현했다(8절 표).
> 관련: 마스터 프롬프트 5.6절(장비·내구도·수리/제작)·6.1절(밤 슬롯 "야간 작업(제작)")·6.2절(생존)·6.3.6절(배낭 업그레이드는 제작/발견), [ROLE_ROOMS_PROPOSAL.md](ROLE_ROOMS_PROPOSAL.md)(방 묶음), [UI_REDESIGN_PROPOSAL.md](UI_REDESIGN_PROPOSAL.md)(다섯 겹), [M7_PLAN.md](M7_PLAN.md)(교실동 특수실·빗물), [BOT_ENDING_LOG.md](BOT_ENDING_LOG.md).
> 부록 C(D1~D26)는 바꾸지 않는다. D5(주 14칸)·D7(강제 휴식)·D25(배낭 종류는 로드아웃으로)·D26(목표 맞추기는 마지막에)을 그대로 따른다.

## 0. 한눈에 보기

| 무엇 | 한 줄 요약 |
|---|---|
| **제작 탭** | 계획 보드 팔레트의 여섯 번째 탭. 물건·설비를 "만드는" 카드를 모은다. 되풀이하는 일(보수·정수·청소)은 생존 탭에 남는다 |
| **작업대가 뿌리** | 창고 방에 작업대를 지으면 새 레시피가 열린다. 작업대 Ⅱ(바이스·공구판)는 3단계 물건의 조건이다 |
| **교실이 해금 조건** | 가사 실습실 = 재봉(가방·보호구), 체육관 = 매트(보호구), 컴퓨터실 = 전자(손전등·자명종), 과학실 = 정수, 현관 = 허수아비. 지금 할 일이 없는 **컴퓨터실에 쓸모가 생긴다** |
| **3단계 줄 7개** | 가방·무기·보호구·손전등·정수·허수아비 + 옮겨 온 방어 설비. 위 단계는 아래 단계 물건을 재료로 먹는다 |
| **연속 칸 잠금** | 큰 물건은 2~3칸이 든다. 낮에 착수하면 뒤 칸이 "제작 중"으로 잠긴다(2칸 = 그날 밤까지, 3칸 = 다음 날 낮까지, 수학여행과 같은 방식). 재료는 착수 칸에 내고 마지막 칸에서 판정한다. 밤 칸 행동 "야간 작업"은 없앤다. 밤에 하는 제작은 이 잠긴 칸이 맡는다 |
| **능력치·숙련** | 손재주는 모든 제작, 지력은 전자·정수, 근력은 무기. 숙련은 공학(무기·도구·전자)·생존(가방·허수아비·필터)·과학(정수기) |
| **좀비 허수아비** | 거점용은 밤 습격 세기를 깎고, 휴대용은 탐험에서 세워 두면 좀비가 사람으로 알고 몰려간다. 사람(깡패·적대적 생존자)은 속지 않는다 |
| **자동 정수기** | 전기 기기(전력 1). 매일 아침 빗물을 저절로 식수로 바꾼다. 냉장고·방송과 여유 전력을 나눠 쓴다 |

**바라는 경험**
- 탐험에서 주워 온 잡동사니가 "다음 탐험을 위한 장비"로 돌아온다(문서 6.3.9 보상 루프).
- 교실을 하나 열 때마다 만들 수 있는 것이 늘어 거점이 자란다는 느낌이 난다.
- 손재주·공학을 키운 판은 장비가 좋고, 다른 판은 주운 장비로 버틴다(육성 체감, 문서 6.3.7).

**옮기는 기준**: 제작 탭 = **물건이나 한 번 짓는 설비를 만드는 카드**. 생존 탭 = **되풀이하는 일**(보수·정수·청소·치료·전력 관리).
C2에 따라 물건·설비 카드 8개를 옮기기로 했는데, 그중 야간 작업은 C3에 따라 없앤다. 그래서 실제로 옮기는 카드는 **7개**다.

**옮길 때 지킬 것**
- 행동 ID·해금 조건·효과·단면도 방은 **하나도 바꾸지 않는다**. 바뀌는 것은 `Category`(Survival → Craft) 한 줄뿐이다.
  - 그래서 세이브(계획 칸은 행동 ID만 저장), 이벤트 조건(`ActionIds`), 봇 그룹(`BUILD`), 역할 방 묶음(`RoleDef.Rooms.Actions`)이 그대로 돈다.
- 제작 탭은 **제작 카드가 하나라도 열리면** 보인다. 작업대는 새 레시피의 조건일 뿐, 옮겨 온 카드를 가리지 않는다(목발은 1막 이야기 깃발로 열리므로 작업대 전에 나올 수 있다).
- 분류에 기대는 곳은 적다(2026-11-24 확인): 이벤트 조건 `ActionCategories`에 `Survival`을 쓰는 곳은 없고(교육 2·탐험 7·휴식 1), 코드에서 `ActionCategory.Survival`을 직접 쓰는 곳은 팔레트 탭 목록뿐이다. 테스트에서 쓰는 곳만 P1에서 확인한다.

### 1.3 조사하며 찾은 틈 (기획에 영향을 주는 것)

1. **헤드리스 탐험이 장비를 보지 않는다.** `HeadlessExpeditionRunner`는 민첩·수면 부채·연속 출정만으로 쓰러짐을 굴리고, 로드아웃(가방·무기·방어구·도구)은 읽지 않는다. 봇도 장비를 고르지 않는다. → 지금 상태로 제작을 넣으면 **봇 결과에 제작 효과가 0으로 잡힌다**. (4.8절) → C5 결정: 반영한다. 제작보다 먼저 따로 한 단계(P2)로 넣는다.
2. **습격 전투력에 장비가 없다.** 문서 5.1.2는 전투력 = … + 장비 보정인데, `DerivedStats.CombatPower`에는 장비가 없다. → **C4 결정: 넣지 않는다.** 장비는 탐험에서만 쓴다. 문서 5.1.2와 다른 이 상태를 그대로 둔다.
3. **무기를 고칠 길이 없다.** 내구도는 창고 묶음마다(`ItemStack.Durability`) 있지만 수리 행동이 없다. 문서 5.6은 "내구도와 수리/제작은 허브 행동과 연결"이라 했다. → 무기 손질 카드를 넣는다.
4. **방어구에는 내구도가 없다.** 무기만 닳는다. → C6 결정: 이번에도 넣지 않는다.
5. **컴퓨터실이 빈 방이다.** `hub_section.json`의 `COMPUTER`는 `Actions: []`이고 어느 역할 묶음에도 없다. 특수실 발견 장면(`EVT_SYS_ROOM_COMPUTER`)만 있다. → 전자 제작실로 쓴다.
6. **탐험 주인공 그림은 무기 4종(방망이·파이프·대걸레·경찰봉)+맨손 × 옷 6벌(교복·여름·겨울·보호대·패딩·진압)뿐이다.** 묶음마다 약 880프레임이라 새 무기·새 옷 그림을 그리는 것은 비싸다. → C10 결정: 지금은 **기존 그림과 아이콘을 빌려 쓴다**(4.6절 `ItemLooks`). 나중에 PixelLab에 맡길 프롬프트는 [PIXELLAB_CRAFTING.md](PIXELLAB_CRAFTING.md)에 따로 둔다.
7. **빗물 공급이 정수 처리량보다 적다.** 생활용수 주 5 + 비 오는 주 10(빗물통이면 +10). 정수 한 번은 12. 자동 정수기는 "물을 더 만드는 것"이 아니라 **정수 칸을 아껴 주는 것**이다. 장마(15~19주, 비 75%)에 빛난다.
8. **조건 엔진에 `ItemCount`·`ActionCount`가 이미 있다.** 레시피 해금·보관 상한을 새 코드 없이 데이터로 쓸 수 있다.

## 2. 제작 탭 UI 흐름

### 2.1 자리 (다섯 겹 구조와의 관계)

| 겹 | 제작이 들어가는 곳 |
|---|---|
| 0겹 장면 (단면도) | 창고 방에 작업대 그림. 지은 설비(필터·끓임 정수대·자동 정수기·현관 허수아비)가 그 방에 보인다. 방을 누르면 그 방 행동 → 팔레트가 그 카드의 탭(제작)으로 넘어간다(`PaletteView.Select`가 이미 분류를 따라간다) |
| 1겹 상시·도크 | 14칸 도크에서 제작 칸은 행동 아이콘으로, 잠긴 뒤 칸은 "제작 중"으로 보인다. 분류 아이콘은 `cat.Craft` |
| 2겹 계획 보드 | **팔레트 여섯 번째 탭 "제작"**: 교육·생존·휴식·일상·탐험 다음 |
| 2겹 보관함 | 만든 장비는 창고로 들어가 보관함 `StorageView` 장비 칸에 그대로 보인다(따로 표시 없음) |
| 3겹 전용 화면 | **설계도** `CraftTreeView`: 탭 머리 단추로 연다. 줄 7개의 3단계를 선으로 잇고, 잠긴 칸에 사유(방·숙련·앞 단계)를 쓴다. 읽기 전용 — 칸을 누르면 팔레트에서 그 카드를 고른 채 닫힌다 |
| 3겹 출정 준비 | 만든 장비를 지금처럼 장착한다. 휴대 허수아비는 배낭에 챙긴다(창고 소모품을 들고 나가는 첫 사례 — 4.3절) |
| 4겹 이야기 | 작업대 첫 장면, 첫 허수아비, 첫 자동 정수기 (P8, 짧은 장면) |

### 2.2 제작 카드

- 한 줄째: 아이콘 · 이름 · 단계 표시(Ⅰ/Ⅱ/Ⅲ) · 장비 칸 칩(무기·가방·방어구·도구·설비·소모품).
- 두 줄째: 재료 칩(자재 3 · 배터리 1 · "나무 몽둥이 1"), 성공 확률, 피로·스트레스.
- 칸 칩: 2칸 이상이면 "2칸 · 그날 밤까지", "3칸 · 다음 날 낮까지"처럼 잠기는 범위를 적는다.
- 카드 아래에 **잠긴 다음 단계 한 장**을 흐리게: "다음: 테이프 감은 몽둥이 — 공학 1 필요". 줄마다 하나만 보여 목록이 길어지지 않는다.
- 비용을 못 내면 지금처럼 `unaffordable`.
- 보관 상한(`MaxOwned`)에 닿으면 "창고에 이미 3개" 로 흐리게.

### 2.3 계획 보드 칸에 놓기

| 규칙 | 내용 |
|---|---|
| 칸 | 제작 카드는 **낮·밤 어느 칸에서나 착수**한다(C11). 2칸 이상 물건은 뒤 칸이 잠기므로 밤에 착수하면 다음 날 낮까지 이어진다. 밤에 착수하거나 이어 한 칸은 밤 작업이다(정전 판정 −) |
| 여러 칸 (C1) | 카드를 놓는 순간 계획 보드가 뒤 칸(`Work − 1`개)을 **"제작 중" 카드로 미리 채우고 잠근다**. 그 칸에 있던 카드는 팔레트로 돌아간다. 착수 카드를 빼면 잠긴 칸도 함께 풀린다 |
| 놓을 수 없는 자리 | 뒤 칸이 주 끝(일요일 밤)을 넘거나, 뒤 칸에 이미 잠긴 칸(다른 제작·수학여행·갇힘)이 있으면 놓지 않는다. 이유를 카드에 한 줄로 쓴다 |
| 미리보기 | "착수(화 낮) → 제작 중(화 밤) → 완성 판정(수 낮)"을 칸마다 보여 준다. 성공 확률은 완성 칸에 붙는다 |
| 주 1회 제한 | 제작에는 `WeeklyGroup`이 없다(동아리·방송과 다름). 자재와 칸이 상한이다. 소모품은 보관 상한으로 막는다 |
| 강제 휴식 (D7) | 탐험 뒤 강제 휴식 칸에 두면 지금처럼 경고 후 허용, 위반 페널티 그대로 |
| 잠긴 칸·여행 | 잠긴 칸·수학여행 중에는 놓을 수 없다(기존 규칙) |
| 실행 연출 | 칸 실행 때 단면도 주인공이 그 방(창고·가사실·체육관·컴퓨터실·과학실·현관)으로 걸어가 작업. 완성 칸이면 머리 위 말풍선(물건 아이콘)과 결과 한 줄 "나무 몽둥이를 만들었다", 결산 일기에 한 줄 |

### 2.4 처음 열리는 흐름

1. 2주차 낮부터 생존 탭에 `작업대 만들기` 카드가 뜬다(자재 3, 1칸). 창고에 탈출한 뒤라 갇힘 1주차와 겹치지 않는다.
2. 작업대를 지으면 결과 한 줄 + 짧은 장면(선생님: "책상 두 개랑 문짝이면 되겠다"), 이후 이 카드는 제작 탭의 맨 위 뿌리로 보인다.
3. 처음 제작 탭을 열면 탭 아래 한 줄 안내 `craft.hint`: "주운 잡동사니로 다음 탐험 장비를 만든다. 교실을 열수록 만들 수 있는 것이 는다."

**자동 정수기와 전력**
- `BalanceConfig.Appliances`에 한 줄 더한다: `{ Id: "PURIFIER", Power: 1, Flag: "AUTO_PURIFIER" }`. 표 순서는 냉장고 → 정수기(용량이 모자라면 앞 것부터 켜진다).
- 발전기 복구 직후 용량은 3이다. 냉장고 1 + 정수기 1 = 2를 쓰면 **여유 전력 1** → 무전(1)은 되지만 방송(2)은 안 된다. 배터리로 용량을 4로 올려야 둘 다 된다. 이 고민이 전력 = 유지력 결정(2026-11-22)의 첫 실전 사례다.
- 정전(발전기 고장 `GENERATOR_BROKEN`)이면 정수기도 멈춘다. 그 주에는 필터 효과만 남는다. 결과 한 줄 "정수기가 멈췄다".
- 정수 순서: 아침에 자동 정수기 → 그 뒤 식사(`UpkeepRules.ApplyMorning`) — 그날 아침 물로 바로 먹는다.
- 빗물 공급(1.3절 7번)이 적어 정수기는 "물 생산"이 아니라 **정수 칸 절약**이다. 빗물통(옮겨 온 카드)과 장마가 함께일 때 가장 크다.
- 단면도: 과학실에 `hub_obj_water_filter`(1단계, 이미 쓰는 그림), 가사실에 `hub_obj_boil_station`, 과학실에 자동 정수기(그림 없음 → 6절).

### 3.7 좀비 허수아비 줄 (현관 → 작업대 → 컴퓨터실)

허수아비는 **마대·빗자루·헌 작업복·양동이 머리**로 만든다. 학생·아이처럼 보이게 만들지 않는다(13장 — 4항 고어 없음, 실제 사람 몸처럼 그리지 않음).

| 레시피 → 물건 | 단계 | 해금 | 재료 | 칸 | 판정 | 효과 |
|---|---|---|---|---|---|---|
| `ACT_CRAFT_SCARECROW` **교문 허수아비** (거점 설비) | Ⅰ | 현관 + 깡통 경보(`ALARM_INSTALLED`) | 자재 3 | 1 | 없음 | `Base.Scarecrow` 내구 3. 밤 습격 세기 −12(`ScarecrowRaidRelief`). 막은 습격마다 내구 −1, 뚫리면 0(쓰러진다). 0이면 다시 만들 수 있다 |
| `ACT_CRAFT_DECOY` → **휴대 허수아비** `ITEM_DECOY_DUMMY` (탐험 소모품) | Ⅱ | 작업대 + 교문 허수아비를 만든 적(`CRAFTED_ACT_CRAFT_SCARECROW`) + 생존 1 | 자재 2 | 1 (2개 나옴) | 0.6 + 손재주 0.004 + 감수성 0.003 + 생존 0.06 | 탐험에서 세우면 좀비가 사람으로 알고 몰려간다(아래). 보관 상한 3(`DecoyMaxOwned`) |
| `ACT_CRAFT_DECOY_BELL` → **울리는 허수아비** `ITEM_DECOY_BELL` | Ⅲ | 컴퓨터실 + 공학 1 + 휴대 허수아비를 만든 적 | 휴대 허수아비 1 + 자재 1 + 배터리 1 | 2 | 0.5 + 지력 0.004 + 공학 0.07 | 자명종 회로: 세우고 6초 조용하다가 울린다. 더 멀리·오래 끈다. 보관 상한 2 |
| `ACT_CRAFT_SCARECROW_BELL` **울리는 교문 허수아비** (거점 설비) | Ⅲ | 컴퓨터실 + 공학 1 + 교문 허수아비가 서 있음 | 자재 2 + 배터리 1 | 2 | 0.5 + 지력 0.004 + 공학 0.07 | 습격 세기 −18, 내구 4로 바꿔 세운다. 깡통 경보와 함께 울려 뚫렸을 때 식량 피해 ×0.8 |

**탐험에서 (휴대 허수아비)**
- 쓰는 법: 배낭에서 우클릭 "세우기"(기존 소모품 쓰기 자리) → 그 자리 바닥에 선다. 1×2 칸, 무게 1.0.
- 소음: 세운 동안 `DecoyNoiseInterval` 4초마다 반경 `DecoyNoiseRadius` 6의 소음(`ThreatSimulation.Emit`, 기존 `NoiseEvent`). 깨어 있는 좀비는 `Investigate`로 다가온다.
- 사람으로 여김: 다가온 좀비는 허수아비를 **표적**으로 붙잡고(공격 상태), 그동안 주인공을 보는 거리가 ×0.5. 좀비 하나가 초당 1씩 깎아 `DecoyHp` 10이 다하면 허수아비가 넘어진다(쓰러짐 연출, 조각나지 않는다). 지속 `DecoySeconds` 40초가 지나도 넘어진다.
- 낮 (C7): 낮에도 세울 수 있다. 다만 휴면 군집도 소음을 듣기 때문에(지금 `Hear`가 `Stirring`을 올린다) **낮에 세우면 군집을 깨울 수 있다**. 낮에 "세우기"를 누르면 경고 문구 `exp.decoy.day_warn`가 한 번 뜬다.
- 사람은 속지 않는다: 적대적 생존자(`ENEMY_SURVIVOR`)는 허수아비를 무시한다. 낮 침입(깡패)에도 거점 허수아비는 효과가 없다.
- 울리는 허수아비: 지연 `BellDecoyDelay` 6초, 반경 9, 지속 60초, `DecoyHp` 16.
- 회수 없음: 한 번 세우면 그 판에서 끝난다(가져오지 못한 소모품과 같다). 쓰러짐(Down) 때 배낭과 함께 잃는다.

**습격에서 (교문 허수아비)**
- `RaidRules.Resolve`: 세기 = 위협 + 분산 − 허수아비 감소. "몰려든 무리 일부가 교문 앞 허수아비에 붙었다"(결과 한 줄 `raid.scarecrow`).
- 습격 확률(`RaidRules.Chance`)은 바꾸지 않는다 — 오는 횟수가 아니라 세기만 줄인다.
- 습격 뒤 위협 해소(`RaidThreatRelief`)는 그대로.
- 단면도: 현관 밖에 허수아비 그림, 쓰러지면 넘어진 그림(6절).

### 3.8 옮겨 온 카드는 트리 어디에

| 줄 | 옮겨 온 카드의 자리 |
|---|---|
| 방어 설비 | 창문 가림막 → 출입구 보강(공학 2, 지금 조건 그대로). 함정(소모품, 최대 3). 깡통 경보 → **교문 허수아비의 조건** |
| 물 | 빗물통(옥상) — 정수 줄과 짝(빗물을 늘리고, 필터·정수기가 처리) |
| 선생님 | 목발 → 간이 의족 (이야기 깃발 `CRUTCH_PLAN`·`PROSTHETIC_PLAN` 그대로) |
| 밤 | 야간 작업은 없앤다(C3). 밤 제작은 2~3칸 물건의 잠긴 칸이 맡는다 |

## 4. 데이터 구조 제안

### 4.1 분류

- `ActionCategory`에 `Craft`를 **맨 끝에** 더한다(정의 DB 에셋의 enum 정수가 밀리지 않게).
- `PaletteView.Tabs`에 `Craft`를 더한다(교육·생존·휴식·일상·탐험·**제작**). 문구 `cat.Craft` = "제작", 아이콘 `cat.Craft` = `icon_craft_workbench`.

### 4.2 레시피 = 행동 (`ActionDef.Craft`)

레시피를 행동으로 두면 계획 칸(행동 ID만 저장)·판정(`CheckDef`)·미리보기·해금(`Unlock`)·봇 그룹·단면도 방이 그대로 돈다. 여러 칸은 기존 칸 잠금(`LockNextSlots`)을 쓴다(C1). 새로 필요한 것은 계획할 때 미리 잠그기와 마지막 칸 판정이다.

```json
{
  "Id": "ACT_CRAFT_CLUB_TAPED",
  "Category": "Craft",
  "SlotTag": "DayOnly",
  "FatigueCost": 7, "StressCost": 1,
  "LockNextSlots": 1, "LockActionId": "ACT_CRAFT_CONTINUE",
  "ResourceCosts": [ { "Resource": "Materials", "Amount": 2 } ],
  "HasCheck": true,
  "Check": { "BaseRate": 0.6, "StatWeights": [ { "Stat": "Strength", "Weight": 0.004 }, { "Stat": "Craft", "Weight": 0.004 } ],
             "UsesProficiency": true, "Proficiency": "Engineering", "ProficiencyWeight": 0.07 },
  "StatGains": [ { "Stat": "Craft", "Amount": 1 } ],
  "HasProficiency": true, "Proficiency": "Engineering", "ProficiencyXp": 1,
  "Unlock": { "FlagsAll": [ "WORKBENCH", "CRAFTED_ACT_CRAFT_CLUB" ],
              "Checks": [ { "Kind": "Proficiency", "Key": "Engineering", "Op": "GreaterOrEqual", "Value": 1 } ] },
  "Craft": {
    "Line": "WEAPON", "Tier": 2, "Work": 2,
    "Product": "ITEM_WEAPON_CLUB_TAPED", "Count": 1,
    "ItemCosts": [ { "ItemId": "ITEM_WEAPON_CLUB", "Count": 1 } ],
    "SetFlags": [], "MaxOwned": 0,
    "Next": "ACT_CRAFT_CLUB_REBAR"
  }
}
```

| `CraftDef` 필드 | 뜻 |
|---|---|
| `Line`, `Tier` | 설계도 화면의 줄·단계, 카드의 Ⅰ/Ⅱ/Ⅲ |
| `Work` | 완성까지 칸 수 (1~3). 불러올 때 `LockNextSlots = Work − 1`을 맞추는지 `ContentValidator`가 점검한다 |
| `Product`, `Count` | 만드는 아이템 (설비면 비움) |
| `ItemCosts` | 착수 때 창고에서 빼는 물건 (앞 단계). 무기는 내구가 가장 낮은 묶음부터 |
| `SetFlags` | 설비 깃발 (`WORKBENCH`·`SAND_FILTER`·`AUTO_PURIFIER`…) |
| `Facility`, `FacilityLevel` | 시설로 두는 설비 (작업대 `WORKSHOP`) |
| `BaseScarecrow` | 거점 허수아비 내구 (교문 허수아비) |
| `MaintainWeapon` | 무기 손질 (손질 비율은 밸런스 값) |
| `MaxOwned` | 창고 보관 상한 (0 = 없음) |
| `Next` | 카드 아래 흐리게 보일 다음 단계 |
| `OnCraft` | 완성 때 더하는 `GameEffect` (깃발·숨김 수치 등, 선택) |

- 기존 `OnSuccess`·`OnGreatSuccess`·`OnFailure`는 제작 카드에서 쓰지 않는다(완성은 `CraftRules`). 옮겨 온 카드(목발·덫 등)는 `Craft` 블록 없이 지금 효과 그대로 — 탭만 옮긴다.
- 공용 잠금 행동 `ACT_CRAFT_CONTINUE`("제작 중"): `Category: Craft`, 낮·밤 공용 칸(3칸이면 밤과 다음 날 낮을 잠그므로). 팔레트에는 안 보인다(수학여행 밤 `ACT_TRIP_NIGHT`처럼 `Unlock: FlagsAll SYSTEM_ONLY`). 피로·스트레스만 든다. 실행 때 `Crafting.Active`의 남은 칸을 하나 줄이고, 0이 되면 완성 판정을 한다.
- 규칙 클래스 `CraftRules`(코어):
  - `CanStart`: 비용·물건·보관 상한, 그리고 뒤 칸이 주 안에 있고 비어 있는지
  - `Start`: 재료를 내고 `Active`를 채운다. 1칸이면 바로 판정한다
  - `Continue`: 남은 칸을 줄이고, 마지막 칸이면 판정한다
  - `Resolve`: 성공·대성공·실패
  - `Complete`: 창고·깃발·시설
  - `Maintain`: 무기 손질
- 계획 잠금: 지금 `LockNextSlots`는 **실행할 때** 뒤 칸을 덮어쓴다. 제작은 **계획할 때** 미리 잠가 보여 준다(`PlanEditor`가 착수 카드를 놓고 뺄 때 뒤 칸을 채우고 비움). 실행할 때의 덮어쓰기도 그대로 두어, 계획이 어긋나도 결과는 같다. 수학여행도 이 미리 잠그기를 쓰게 할 수 있지만 이번 범위가 아니다.
- 미리보기(`PlanInsights`): 착수·제작 중·완성 판정을 칸마다 보여 주고, 비용은 착수 칸에서 계산한다.

### 4.3 아이템 정의 새 필드 (`ItemDef`)

| 필드 | 쓰는 곳 | 기본 |
|---|---|---|
| `LightRange` | 손전등 시야 배율 (`FlashlightViewDistance` × 값) | 1 |
| `LightExposure` | 켰을 때 노출 (0이면 `BalanceConfig.FlashlightExposure`) | 0 |
| `ExtraTools` | 도구 칸 하나로 더 하는 일 (`[Crowbar]`) | 빈 목록 |
| `Decoy` | 허수아비 블록: `Seconds`·`NoiseRadius`·`NoiseInterval`·`Hp`·`Delay` | 없음 |

- 휴대 허수아비는 `Slot: Consumable` + `Decoy` 블록. 탐험 배낭 우클릭 "쓰기"가 `Decoy`면 "세우기"로 바뀐다.
- **창고 소모품을 들고 나가기**: 지금은 퀵슬롯을 없애 창고 소모품을 들고 나갈 길이 없다(PROGRESS "하면 좋을 작업"). 허수아비가 첫 사례라 출정 준비 화면에 "챙길 것" 칸(배낭에 미리 넣기, 무게·칸 차지)을 함께 만든다(P6). 다른 소모품(붕대 등)도 이 칸을 쓸 수 있게 일반으로 만든다.

### 4.4 상태·세이브 (v13 → **v14**)

| 새 상태 | 내용 |
|---|---|
| `GameState.Crafting.Active` | 진행 중인 제작 하나: 레시피 ID·남은 칸 수 (없으면 비움). 주 안에서만 쓰고, 주가 끝나면 늘 비어 있다 |
| `BaseState.Scarecrow` | 교문 허수아비 남은 내구 (0 = 없음) |
| (깃발) | `WORKBENCH`·`SAND_FILTER`·`BOIL_STATION`·`AUTO_PURIFIER`·`SCARECROW_BELL`·`CRAFTED_*` — 깃발은 지금 저장 구조 그대로 |
| (시설) | `WORKSHOP` 단계 — `Base.Facilities` 그대로 |

- 변환: 야간 작업 칸을 `ACT_REST_NIGHT`로 바꾸는 v12 → v13은 P1에서 먼저 넣었다(계획·지난주 계획·프리셋). P3의 v13 → v14는 빈 `Crafting`, `Scarecrow` 0만 넣는다.
- 만든 물건은 기존 `Storage`(`ItemStack` + `Durability`)에 들어가므로 구조 변경이 없다.

### 4.5 `BalanceConfig` "제작" 절 (초안 값)

| 값 | 초안 | 뜻 |

## 5. 밸런스 위험과 확인 방법

봇 결과는 **전략별 엔딩 확률 + 방향성**만 보고하고, 단계마다 [BOT_ENDING_LOG.md](BOT_ENDING_LOG.md)에 새 절로 잇는다. 목표 맞추기(배드 45~55% 등)는 하지 않는다 — 마지막에 한 번에(D26).

| # | 위험 | 왜 | 확인 방법 |
|---|---|---|---|
| R1 | **기준선이 흔들린다** | 헤드리스 장비 반영(`[C5]`)은 제작이 없어도 주운 가방·무기의 효과를 처음 셈한다 | P2를 제작보다 먼저 따로 커밋하고 BOT_ENDING_LOG에 "장비 반영" 절을 따로 둔다. 제작 효과와 섞지 않는다 |
| R2 | 자재 쟁탈 | 바리케이드·보강·전력 복구와 같은 자재를 쓴다 → 방어가 약해져 습격이 더 뚫릴 수 있다 | 봇 보고 "자재 바닥난 주", 습격 뚫림 방향. 쏠리면 1단계 재료를 자재 1로 |
| R3 | 물 걱정이 사라진다 | 장마 + 빗물통 + 자동 정수기 | 사망 원인 "갈증" 방향, 정수 칸 수 방향. 너무 줄면 `AutoPurifyDaily` 3 → 2 |
| R4 | 습격이 시시해진다 | 교문 허수아비 −12에 함정·경보가 겹친다 | 습격 뚫림 비율 방향. 쏠리면 내구 3 → 2 |
| R5 | 밤 탐험 격차 | 휴대 허수아비·헤드랜턴이 밤을 쉽게 한다 → NIGHT_ONLY 배드(지금 75%)가 크게 준다 | 전략별 배드 방향. 격차를 줄이는 건 좋은 쪽이지만, 맞추기는 마지막 |
| R6 | 교육 칸이 준다 | 낮 칸을 제작에 쓰면 특화 엔딩(지금 12%, 이미 모자람)이 더 줄 수 있다 | 특화 비율 방향. 제작이 손재주·공학 성장을 주므로 공학 특화 쪽은 오를 수도 있다 |
| R7 | 미끼 남용 | 수동 플레이에서 허수아비로 좀비를 계속 끈다 | 보관 상한 3, HP·지속, 낮 군집 깨움. 플레이 기록(`expeditions.jsonl`)에 허수아비 사용·그 뒤 쓰러짐을 남겨 본다 |
| R8 | 3단계가 너무 세다 | 위력 3은 배회 좀비를 한 번에 | 플레이 기록의 무기별 맞힘·쓰러짐. 세면 위력 2 + 내구 22 |
| R9 | 발견 장비 가치 | 3단계가 희귀 전리품(진압 조끼·등산 배낭·경찰봉)을 덮는다 | 3단계에 무게·소음 대가를 두었다. 봇 보고에 장착 장비 출처(만든 것/주운 것) 비율 |
| R10 | 전력 막힘 | 자동 정수기가 방송(여유 2)을 막는다 | 방송 횟수 방향(`BROADCAST` 응답 장면 비율). 의도된 고민이지만 방송 줄기가 닫히면 C8에서 미뤄 둔 기기 끄기·켜기를 더한다 |

**확인 순서 (단계마다)**
1. EditMode 테스트: `CraftRules`(착수 비용·앞 단계 소비·뒤 칸 잠금·주 끝 막기·마지막 칸 판정·실패 환불·대성공·완성·보관 상한), 세이브 v13 → v14, 자동 정수기 아침 정수·정전 정지, 허수아비 습격 세기·내구, 헤드리스 장비 반영(같은 시드에서 장비 없음 = 지금과 같은 결과).
2. 52주 헤드리스 `FullYear_MixedStrategy_ReachesRescueEnding`이 그대로 통과.
3. 봇 5전략 × 40판(표준) → BOT_ENDING_LOG 새 절(확률 + 방향성).
4. 직접 플레이: 탐험에서 허수아비 세우기·헤드랜턴·멀티툴, 단면도 설비 그림, 제작 탭·설계도.

**C1·C3 결정으로 달라진 점**
- 큰 물건(2~3칸)을 만드는 날에는 그날 밤도 쓴다. 그래서 밤 탐험이나 경계 서기와 칸을 놓고 고민하게 된다.
- 주를 넘기는 진행이 없어서 세이브 v14의 새 상태는 주 안에서 쓰는 `Crafting.Active` 하나와 교문 허수아비 `Base.Scarecrow`뿐이다.
- 3칸 물건은 주의 여섯째 날(토요일) 낮까지 착수해야 한다. 2칸 물건은 일요일 낮에도 된다. 그보다 늦으면 뒤 칸이 일요일 밤을 넘는다.
- 계획할 때 뒤 칸을 미리 잠그는 것은 새로 만든다. 지금 칸 잠금은 실행할 때만 뒤 칸을 덮어쓴다.

## 9. 지키는 것 (점검)

- 부록 C 결정을 바꾸지 않는다: 주 14칸(D5), 강제 휴식(D7), 배낭은 로드아웃으로 바꾼다(D25 — 만든 가방도 출정 준비·탐험 장착), 목표 맞추기는 마지막(D26).
- 콘텐츠 안전(13장): 무기는 둔기·찌르기만, 맞으면 쓰러짐·암전 연출 그대로. 허수아비는 사람·아이처럼 그리지 않고(마대·양동이 머리), 넘어질 때 조각나지 않는다. 사람(깡패·적대적 생존자)을 속이거나 해치는 용도로 쓰지 않는다. 실존 상표·학교 이름 없음.
- 수치·문구는 데이터에: 레시피·아이템은 `crafting.json`, 값은 `BalanceConfig` 제작 절, 문구는 `ko.json`, 그림 빌리기는 `exploration_art.json`.
- 코어(`ApoGirl.Core`)는 UnityEngine을 참조하지 않는다: `CraftRules`·헤드리스 반영은 코어, 허수아비 표적·세우기는 탐험 런타임.
- PC 전용: 키보드·마우스(배낭 우클릭 "세우기").
- 사용자 로컬 파일(`balance_overrides.json`·`BalanceConfig.asset`·`balance_sections.json`·Settings)은 건드리지 않는다.
